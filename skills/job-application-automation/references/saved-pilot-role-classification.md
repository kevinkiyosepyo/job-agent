# Saved-pilot role classification

Use `terminal` with `scanner.py INPUT --profile CANONICAL_PROFILE --queue-db CANONICAL_QUEUE --output PRIVATE_REPORT` only after inspecting the installed CLI. This is local discovery classification, not a submit command. Do not pass `--notify-maango` for a routine regression and never use a tracker-reading path without explicit authorization. The scanner has no `--dry-run` flag; its normal default reads the queue without mutation and writes a discovery report. Keep output under the pilot runtime, not the production scan-results path.

- Preserve the exact employer title, URL and source provenance. Use saved public bytes as non-live evidence; never turn a synthetic test into a candidate.
- `Software Developer` and frontend-engineer spelling aliases (`Frontend`, `Front-End`, `Front End`) are considered only when `Software Engineer` is a configured target. These are role-label synonyms, not verification of a posting's required skills. Target level/seniority, geography, timeline, sponsorship, MAANGO and durable duplicate checks still apply. Do not broaden the canonical profile to make a test pass.
- A corrected role match is not qualification approval. Unknown location remains `needs_verification`; a missing bonus skill is not a mandatory qualification. Saved report fields called `relevant` or `auto_apply_queue` do not establish active listing state, portal deduplication, supported preparation, Review provenance or submit authority.
- The scanner CLI quarantines explicit non-live/pilot provenance into `observation_only_results`; those URLs are absent from `new`, `auto_apply_queue`, actionable `manual_only` and MAANGO notification dispatch. It checks the source adapter's `source_live_verified` as well as `live_verified` and `pilot_only`: only boolean `source_live_verified=true`, `live_verified=true` and `pilot_only=false` count as non-quarantining values when those fields are present; malformed values fail closed. No true marker overrides a false/malformed marker elsewhere. A non-live marker on any duplicate normalized URL quarantines that URL even if the first retained row lacks the marker. First-row identity/hints are still retained, not relabelled as verified. This is a batch-local discovery boundary, not a new ledger or a universal executor safeguard. Missing provenance retains legacy discovery behavior and is not proof of live verification. Do not strip the markers or route `all_results` / observations into execution.
- Before any actual execution, apply the umbrella's canonical profile/resume, exact listing, shared intent ledger and one-shot authorization gates. An unresolved intent remains observation-only.

Verification through `terminal`: run `run_offline_tests.py tests/test_scanner_source_provenance.py tests/test_scanner_observation.py tests/test_scanner_frontend_roles.py tests/test_scanner_software_developer.py tests/test_scanner.py -q`, then the full guarded suite. Replay the same saved-title input before/after and compare the exact rejection reason, unchanged title/URL, remaining verification gates and zero external notifications. For a source-provenance repair, require all classification records unchanged and every flagged source row moved into observations, not an actionable queue. No browser, Sheets or employer mutation is needed for this regression.
