# Lever public inspection and capability limits

Use the saved-HTML `prepare_job.py` or `lever_handler.py` CLI only for non-submitting inspection. A saved snapshot can be replayed while the canonical shared ledger has an unresolved intent: these readers do not grant authorization or erase history. Do not use a separate ledger or reinterpret an unresolved submission to unblock browser work.

1. Preserve the exact official listing/application URL, posting identifier, retrieval time and source-byte digest. Employer requisition and ATS public posting ID are different fields; do not invent an unpublished requisition. The inspector reads a unique `h2` and unique `.posting-category.location` within one `.posting-header`, with legacy h1/location fallback. Multiple headers/values do not permit choosing by position. These are static identity strings, not current eligibility or employer acceptance. The company value remains a URL-derived board label, not a verified legal employer name.
2. Inspect official body and application controls separately. An HTTP 200 or a script-only shell is not complete form evidence. Do not infer active dates from generic semester options.
3. Lever question containers may use `.application-question` and `.application-label` rather than `label[for]`. The inspector recovers those headings and exposes static radio/checkbox `choice_groups` keyed by question card, exact control name and control type. Options keep separate labels and raw values; do not trim values. `source=static_html` and `bound_values_verified=false` explicitly mean no saved-state evidence. A checkbox group's `required` flag reports an input's `required` or `aria-required="true"` markup; it does not mean select every option or establish minimum/maximum counts. Preserve wording such as `Select 1-3` or `Please pick 1-2` and verify actual rendered constraints before filling. Native select definitions are exposed separately in `select_groups`: each control retains raw ID and the shared inventory name key (`name` with `id` fallback; empty/missing both becomes an empty string), question label, required/multiple flags, its own disabled attribute and exact option definitions. Options retain raw value attributes (missing is null, empty placeholder is an empty string), label attributes or whitespace-normalized text, and disabled attribute/optgroup inheritance. No selected attribute is presented as a bound answer. Duplicate control names stay separate; this is not uniqueness/targeting proof. Disabled metadata is markup-only, not effective rendered interactability (fieldset, CSS and dynamic state still require a fresh live read). Native option/optgroup end-tag omission is handled locally without changing shared parsing or manual-gate policy. `select_groups` does not cover arbitrary custom dropdowns. Blank labels, lost options or blank role identity mean an incomplete inspector, not absent questions.

For explicit `[data-qa="additional-cards"]` containers, `fields` and radio/checkbox `choice_groups` may also retain a separate `card_heading` from one direct-child `h4[data-qa="card-name"]`. Read it alongside a generic prompt such as `Select One`; never replace the field prompt with the card heading or treat a shared card title as one answer for all fields. Multiple/missing/direct-child mismatches remain unknown. Hidden base-template JSON is not parsed for this context. This metadata is static markup, not proof of rendered visibility or a new answer-engine mapping.

For school/source/year dropdowns, inspect the actual native option set before searching or supplying free text. Load `education-school-picker` for exact campus matching. A school directory label may use punctuation not present in the canonical name; verify the exact institution, never substitute another campus. Missing value attributes are not guessed into runtime values by this static inspector. Under a separately authorized live flow, select by the real option value, verify selectedOptions and saved Review, and retain all existing one-shot gates. Do not auto-select a placeholder or an unsupported referral default.
4. Ignore dormant libraries, templates and explicitly hidden integration text as gate evidence. `aria-hidden` alone is not visual hiding. Conflicting inline styles must remain uncertain. A null static manual gate does not verify rendered clearance: scripts, CSS classes, iframe challenges and submit-time errors need a fresh approved browser read.
5. Upload status strings such as `Success!`, analyzing/failure templates and filename text are not proof of a browser File object, byte digest, saved Review or employer acceptance.
6. Keep required answers, employer eligibility and automation support distinct. A mandatory Yes/No question does not itself prove that Yes is a qualification. Unknown material facts stay parked without declaring the role ineligible.
7. Observe only when the normal-profile transport is unavailable. Do not launch a new browser, change security settings or replay uncertain actions. A read-only transport failure should be checkpointed promptly, not retried for hours.

Tests: use `run_offline_tests.py` with the installed interpreter and focused test path, followed by the full guarded suite. The guard must retain the browser-launching exclusions. Static regression success is not connected ATS preparation/Review/confirmation support.

Report inspected, filled, Review-verified, submitted, confirmed and notification-verified separately. Submission requires the existing canonical ledger, independent grounded Review, current canonical resume bytes, single-use authorization and one-shot path. Notifications must not turn preparation into Applied; Sheets remain opt-in.
